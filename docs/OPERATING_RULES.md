# 수업 운영 규칙

## 교수법
- 소크라테스식: 상황 제시 → 질문 → 학습자의 추론 → 원리 정리 → 독립 구현 → 피드백
- 질문만 계속하지 않는다. 막힌 경우 먼저 오개념을 설명한다.
- 학습자가 답하기 전에는 문제의 완성 코드를 제공하지 않는다.
- 단원마다 실제 제품 기능과 연결할 기회를 찾되, 기초를 건너뛰지 않는다.

## AI 사용 정책
- **Drill / Challenge / 진급시험:** AI가 정답 코드나 완성 코드를 작성하는 것 금지.
- 개념 질문 및 오류의 원리 설명은 가능하나, 독립 평가 중에는 평가 규칙을 우선한다.
- **실제 SaaS Project:** AI 코드 생성 가능. 결과를 설명·테스트·검토해야 한다.
- AI 사용 여부는 제출자가 스스로 표기한다. 원격으로 완전한 진위를 확인한다고 주장하지 않는다.

## 진도
- 진단평가는 배치용이며 합격/불합격 없음.
- 종합 진급시험 100점 중 **85점 이상**, 필수 테스트 통과, 핵심 오개념 해소가 원칙.
- 미통과 시 다른 문제로 재평가. 같은 답을 외워 통과하지 않는다.
- 프로젝트의 매출과 개발 역량은 서로 독립된 평가축이다.

## 사업 원칙
- 첫 고객은 소상공인·1인 사업자·소기업을 조사한다.
- 연락 채널은 동의 기반 온라인 메시지·이메일·허용된 커뮤니티 게시글 중심.
- 제품 아이디어는 사용자와 튜터가 각각 제안하고 같은 기준으로 비교한다.
- 실제 고객 수요 검증 전 장기간 개발하지 않는다.

## 보안/공개
- 이 저장소는 현재 PUBLIC이다. 개인 성적 세부기록·고객 이름·연락처·비밀번호·API 키를 커밋하지 않는다.
- 민감한 기록은 개인 비공개 저장소 또는 로컬 `progress/private/`에 두고 .gitignore로 제외한다.
